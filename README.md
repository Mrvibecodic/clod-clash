## Что это

Clod Clash — сборка Clash Verge Rev, доведённая до состояния «клиент для клиентов панели»:
пользователь вставляет ссылку на подписку и нажимает одну кнопку. Всё, что панель хочет
сообщить клиенту — название тарифа, логотип, объявление, ссылку на кабинет и поддержку,
лимит устройств, смену адреса подписки — приложение понимает и показывает.

Ядро Mihomo не модифицируется: используется официальный бинарник и штатный REST/IPC.
Вся техническая часть Clash Verge Rev (правила, соединения, логи, редакторы конфигов)
сохранена — она просто убирается с глаз в расширенный режим.

> **Статус: альфа.** Релизы выходят как pre-release, автообновление работает
> (канал `updater`). Настройка панели — в [docs/REMNAWAVE.md](./docs/REMNAWAVE.md).

## Отличия от Clash Verge Rev

| Возможность | Clash Verge Rev | Clod Clash |
| --- | --- | --- |
| Заголовки подписки Remnawave / Happ | 4 заголовка | 27 заголовков + 5 синонимов для совместимости, см. ниже |
| Идентификация устройства (`x-hwid`) | нет | есть, с обработкой лимита устройств |
| Резервный адрес подписки | нет | `fallback-url` и `fallback-domain` |
| Смена адреса подписки провайдером | нет | `new-url` / `new-domain`, с проверкой нового адреса |
| Логотип, объявления, кабинет, поддержка | частично | есть |
| Безлимитный трафик / бессрочная подписка | показывает `0 B` и `-` | «Безлимит» / «Бессрочно» |
| Расход трафика между обновлениями подписки | показывает только цифру панели | досчитывает сам и помечает сумму как примерную |
| Переключатели подключения | только в настройках | плюс карточка «Быстрые действия» на главной расширенного режима |
| Обновление ядра Mihomo отдельно от приложения | нет | есть (управляемое ядро в настройках) |
| Простой режим интерфейса | нет | есть, одна кнопка Connect |
| Выбор сервера | сбрасывается тестом задержек и обновлением подписки | строго сохраняется; избранные — вверху списка и как автозамена недоступному |
| Режим TUN | служба ставится вручную, при её отсутствии TUN молча выключается | служба ставится сама при первом запуске (один запрос прав), выбор пользователя не стирается, провал старта виден |

## Режим TUN

TUN перехватывает трафик всех приложений, включая те, что не умеют ходить через системный
прокси. Для него нужен привилегированный помощник — фоновая служба; в Clash Verge Rev её
ставят руками из настроек, и до тех пор переключатель TUN недоступен.

Здесь это сделано так, чтобы пользователь трогал только сам переключатель:

* **Служба ставится сама.** При первом запуске, уже после появления окна, приложение
  проверяет TUN и, если помощника нет, ставит его — один запрос прав (UAC на Windows,
  пароль администратора на macOS, `pkexec` на Linux). С правами поднимается **только
  установщик службы**: само приложение и его WebView остаются непривилегированными.
* **Отказ уважается.** Если запрос прав отклонён или установка не удалась, приложение
  работает дальше через системный прокси и больше не спрашивает само — до следующего
  обновления версии. Переключатель TUN при этом остаётся рабочим: включение = «поставь
  службу и включи», это уже просьба пользователя.
* **Выбор пользователя не стирается.** Раньше приложение при старте писало
  `enable_tun_mode: false` прямо в конфиг, если служба не успела ответить — а при
  автозапуске она отвечает позже приложения. Теперь недоступность действует только на
  текущую сессию, файл настроек не трогается.
* **Ядро не ждут молча.** Если служба поднимается медленнее приложения, ядро стартует без
  неё и переезжает на службу, как только та ответит, — без разрыва соединений. Это работает
  на всех трёх системах.
* **Факт вместо обещания.** Вывод ядра разбирается: если mihomo не смог поднять устройство
  (`Start TUN listening error: … operation not permitted`), TUN честно гаснет, а не остаётся
  зелёным при мёртвом туннеле. Если ядро упало само, оно перезапускается — до трёх попыток
  подряд.
* **Это видно на экране, а не только в уведомлении.** Пока ставится служба, под
  переключателями (в простом режиме — под кнопкой Connect) висит строка «Настраиваем TUN —
  подтвердите запрос системы»: она видна за системным окном и объясняет, кто его показал.
  Если TUN не поднялся, там же остаётся «TUN не запустился, трафик идёт мимо туннеля» с
  кнопкой «Настроить» — тост исчезает, строка нет.

## Заголовки подписки

Это главное, ради чего сделан форк. Ниже — всё, что клиент отправляет и понимает.

### Что клиент отправляет панели

Отправляется с **каждым** запросом подписки — при импорте, при ручном и при автоматическом
обновлении.

| Заголовок | Значение | Зачем |
| --- | --- | --- |
| `User-Agent` | `ClodClash/0.0.9-alpha` | по нему панель узнаёт клиент (правило `^clodclash`) и видит его версию в списке устройств. Формат «имя/версия» — как у koala-clash |
| `Accept` | `*/*` | без этого панель может принять клиент за браузер и отдать HTML-страницу вместо конфига |
| `x-hwid` | 32 hex-символа | идентификатор устройства для лимита устройств |
| `x-device-os` | `Windows` / `macOS` / `Linux` | показывается в списке устройств в панели |
| `x-ver-os` | человекочитаемая версия ОС: `24H2`, `15.5`, `Ubuntu 24.04` | то же |
| `x-device-model` | редакция/модель системы: `Windows 11 Pro`, `MacBookPro18,3 (M1 Pro)`, `Ubuntu 24.04.1 LTS`. Имя компьютера **не** отправляется | то же |

Четыре заголовка `x-*` отправляются, только пока включена настройка «идентификация
устройства» (по умолчанию включена). Если пользователь её выключит — не отправляется
ни один из них.

### Что клиент понимает в ответе панели

**Описание подписки**

| Заголовок | Что означает | Что делает приложение |
| --- | --- | --- |
| `profile-title` | название тарифа | ставит имя профиля. Имя, заданное пользователем вручную, не перетирается |
| `profile-logo` | ссылка на логотип провайдера | скачивается при обновлении подписки и хранится локально: логотип не мигает при старте, работает офлайн и не тянется с чужого хоста при каждом показе экрана. Для подписки, добавленной до появления кэша, файл дотягивается один раз при первом показе. Скачивается сначала через собственное ядро и только потом обычным маршрутом — картинка не стоит того, чтобы отдавать чужому хосту настоящий адрес. Принимаются `png`, `jpeg`, `webp`, `avif`, `gif`, `svg`, `bmp`, `ico` не тяжелее 2 МБ; ответ другого типа не сохраняется, и логотип грузится по исходной ссылке, как раньше. Только `https`, причём и после редиректов: увести клиент на `http://` или в локальную сеть заголовком нельзя |
| `subscription-userinfo` | `upload`, `download`, `total`, `expire` | трафик и срок на карточке подписки. `total=0` → «Безлимит», `expire=0` → «Бессрочно» |
| `subscription-refill-date` | unix-время пополнения трафика | «Трафик обновится {дата}» |
| `profile-update-interval` | интервал автообновления в часах | ставит интервал и помечает его как заданный провайдером — пользователь не сможет его переопределить |
| `content-disposition` | имя файла | запасной вариант имени профиля, если нет `profile-title` |

**Связь с провайдером**

| Заголовок | Что означает | Что делает приложение |
| --- | --- | --- |
| `clod-portal-url` | ссылка на личный кабинет провайдера | кнопка «Личный кабинет». **Свой заголовок, а не `profile-web-page-url`:** у Remnawave последний обычно ведёт на страницу самой подписки, а кабинет — это место, где клиент продлевает тариф. Только `https` |
| `profile-web-page-url` | страница подписки у провайдера | делает имя тарифа на карточке кликабельным. Только `https` |
| `support-url` | ссылка на поддержку | кнопка «Поддержка»; для `t.me/…` показывается иконка Telegram. Только `https`, `tg:` или `mailto:` |
| `announce` | постоянное объявление провайдера | баннер в приложении **без крестика** — живёт ровно столько, сколько панель его отдаёт. Поддерживает подсветку слов цветом (см. ниже). Для разовых акций используйте `clod-promo` |
| `announce-url` | куда ведёт клик по объявлению | делает баннер `announce` кликабельным. Только `https` |
| `clod-promo` | временный промо-баннер (акции, скидки) | отдельный акцентный баннер, который **можно закрыть**, с той же подсветкой слов цветом, что и `announce`. При изменении текста показывается снова; если панель перестала слать заголовок — исчезает на следующем обновлении подписки. Чтобы промо не пропадало «просто так», у подписки должно быть включено автообновление (см. `profile-update-interval`) |
| `clod-promo-url` | куда ведёт клик по промо | делает баннер `clod-promo` кликабельным. Только `https` |
| `clod-renew-url` | ссылка на продление тарифа | показывает кнопку **«Продлить»** (в расширенном режиме и при критическом остатке). Без заголовка кнопки нет. Только `https` |
| `clod-topup-url` | ссылка на докупку трафика | показывает кнопку **«Докупить трафик»**. Без заголовка кнопки нет. Только `https` |

**Смена адреса подписки**

| Заголовок | Что означает | Что делает приложение |
| --- | --- | --- |
| `new-url` | новый адрес подписки | адрес заменяется **только** после успешной пробной загрузки по нему. Старый сохраняется в истории |
| `new-domain` | новый домен (можно `host:port`) | меняется только хост, путь и параметры ссылки сохраняются. Проверка та же, что у `new-url` |
| `fallback-url` | резервный полный адрес | используется, только если основной адрес не ответил. Основной адрес при этом **не** заменяется |
| `fallback-domain` | резервный хост для основного адреса | пробуется после `fallback-url`. Порядок: основной → `fallback-url` → основной с подменённым хостом |

Подряд разрешено не более **трёх** переездов по `new-url`/`new-domain`: это защита от двух
панелей, которые перекидывают клиент друг на друга по кругу. Счётчик обнуляется, как только
приходит обновление без запроса на переезд.

**Лимит устройств**

| Заголовок | Что означает | Что делает приложение |
| --- | --- | --- |
| `x-hwid-active` | устройство зарегистрировано | ничего, информационный |
| `x-hwid-not-supported` | панель требует идентификатор, а клиент его не прислал | диалог «Провайдер требует идентификацию устройства. Включить?». **Рабочий профиль не затирается** — тело ответа здесь такая же заглушка, как при лимите. Важнее `x-hwid-limit`: Remnawave ставит тот в обеих ветках блокировки, и без этого приоритета пользователь получал бы сообщение о лимите, которого не достигал |
| `x-hwid-max-devices-reached`<br>`x-hwid-limit` | лимит устройств исчерпан | диалог с текстом из `announce` и кнопкой «Поддержка». **Рабочий профиль не затирается** — ответ панели в этом случае пустой |
| `x-hwid-max-devices` | сколько устройств разрешено | подставляется в текст диалога. Remnawave 3.x его не шлёт — без него диалог просто остаётся без числа |

**Уведомления**

| Заголовок | Что означает | Что делает приложение |
| --- | --- | --- |
| `notify-expire-days` | за сколько дней предупреждать: `7,3,1` или `off` | системные уведомления о скором окончании срока |
| `notify-traffic-percent` | пороги израсходованного трафика: `80,90,100` или `off` | системные уведомления о расходе трафика |
| `notification-subs-expire` | Happ-совместимость | если наших заголовков нет — включает напоминания о сроке со значениями по умолчанию |

**Управление интерфейсом**

| Заголовок | Что означает | Что делает приложение |
| --- | --- | --- |
| `clod-simple-mode` | `1`/`0` — простой или расширенный вид | подсказывает режим интерфейса. **Выбор пользователя всегда важнее** этого заголовка. Совместимость: распознаются также `pxa-simple-mode` (Prizrak-Box) и `flclashx-newboard` (FlClashX) |
| `clod-lock-mode` | `1`/`0` — запретить смену режимов в приложении | скрывает из настроек переключатели «Подключение: системный прокси / TUN» и выбор режима маршрутизации, оставляя только строку-статус. Совместимость: `global-mode: false` (Prizrak-Box) понимается как `clod-lock-mode: 1` |

### Правила разбора

Действуют для всех заголовков выше:

* **Регистр не важен.** `Profile-Title`, `profile-title` и `PROFILE-TITLE` — одно и то же.
* **Префиксы объектных хранилищ принимаются.** Если подписка лежит в S3-совместимом
  хранилище, заголовки приезжают как `x-amz-meta-profile-title`, `x-obs-meta-support-url`
  и подобные — они распознаются. При этом посторонний заголовок вроде `renew-url`
  **не** будет принят за `new-url`.
* **Значение с префиксом `base64:` декодируется.** Понимаются четыре алфавита: обычный,
  без выравнивания, url-safe и url-safe без выравнивания. Если декодировать не удалось,
  берётся исходная строка.
* **Кириллица и другой не-ASCII текст читаются в двух видах:** и как `base64:`, и как
  сырой UTF-8 прямо в значении заголовка. Формально второе запрещено стандартом, но
  панели так делают, поэтому клиент это переживает.
* **Перевод строки в значении заголовка невозможен.** Многострочное объявление панель
  обязана отдавать через `base64:` — иначе оно физически не доедет.
* **Ссылки проверяются, http запрещён.** `profile-logo`, `profile-web-page-url`,
  `announce-url`, `clod-portal-url`, `clod-promo-url`, `clod-renew-url` и
  `clod-topup-url` принимаются **только по `https`** — голый `http` (как и
  `javascript:`/`file:`) отбрасывается. `support-url` дополнительно понимает
  `tg:` и `mailto:`. `new-url` не может понизить `https` до `http`. Кнопки
  «Личный кабинет», «Продлить» и «Докупить трафик» появляются **только** при
  наличии соответствующего заголовка — приложение само платёжных ссылок не
  выдумывает.
* **Расход трафика между обновлениями подписки досчитывается на клиенте.**
  Панель пересчитывает `subscription-userinfo` не чаще раза в час, поэтому
  поверх её значения складывается то, что прошло через прокси уже после неё
  (по `/connections` ядра, соединения в обход прокси не считаются). Такая сумма
  показывается с `≈` и жёлтым треугольником, рядом — кнопка обновления
  подписки. Само число из подписки остаётся истиной: статусы «трафик
  закончился», критические состояния и кнопки продления считаются **только** по
  нему. Клиентский счёт может быть занижен (короткие соединения между опросами,
  трафик других устройств той же подписки), но никогда не завышен.
* **Пустые значения игнорируются**, объявление обрезается до 500 символов, списки
  порогов проверяются по диапазону (1–365 дней, 1–100 процентов) и ограничены десятью
  значениями. Полностью некорректный заголовок обрабатывается так же, как отсутствующий.

### Цвет в объявлениях

`announce` и `clod-promo` умеют подсвечивать отдельные слова. Код цвета пишется
**вплотную** к слову, без пробела:

```
announce: #EF4444ВАЖНО: узел #F59E0BНидерланды на профилактике до 05:00
```

* красится одно слово — от кода до ближайшего пробела;
* синтаксис совместим с Prizrak-Box, поэтому панель, уже настроенная под него,
  работает без изменений;
* код цвета не занимает место в лимите 500 символов — считается только видимый текст;
* `#EF4444` **с пробелом** после кода, `#XYZ`, `#12` и обычная решётка в тексте
  остаются текстом;
* берутся ровно шесть знаков после решётки: в `#1234567` цветом `#123456`
  красится оставшаяся `7`;
* два подряд покрашенных слова разделяйте пробелом — `#EF4444раз #00FF00два`.
  Без пробела второй код попадёт внутрь первого слова и покажется как текст;
* цвет применяется как прислали, в светлой и тёмной теме одинаково — приложение
  не подгоняет фирменный цвет провайдера под свою палитру.

### Узлы-заглушки панели

Remnawave на истёкшую подписку, исчерпанный трафик, отключённого пользователя и
ненастроенные хосты отвечает не ошибкой, а **HTTP 200 и валидным конфигом**, в котором
вместо серверов лежат узлы-заглушки: `server: 0.0.0.0`, `port: 1`, нулевой `uuid`.
Имена у них произвольные — «Subscription expired», «Contact support», «→ No hosts found»
и любые другие, которые администратор задал в настройках панели.

Клиент такие узлы **вырезает из конфига до того, как он уедет в ядро**: они не появляются
в списке серверов, не участвуют в тесте задержки и не могут быть выбраны автоматикой.
Проверка структурная (адрес, порт, нулевой идентификатор), а не по имени — имена панель
отдаёт на своём языке и меняет их когда угодно. Локальный адрес (`127.0.0.1`) заглушкой
**не** считается: это рабочая схема с локальным релеем.

Если в группе не осталось ни одного узла, клиент подставляет в неё `REJECT`: на пустую
группу mihomo отвечает `` `use` or `proxies` missing `` и не стартует вовсе, а `DIRECT`
пустил бы трафик мимо туннеля. Проверка идёт последней, уже после чистки битых ссылок,
и не зависит от того, была ли в конфиге хоть одна заглушка: панель умеет прислать просто
пустой `proxies`, а имена узлов в группе прописаны шаблоном — результат тот же.

Не трогаются только группы, которые ядро наполнит само: с `include-all` или
`include-all-proxies` (mihomo подставляет в них `COMPATIBLE`), с `include-all-providers`
при наличии хотя бы одного `proxy-providers` и с `use:`, где указанный провайдер реально
объявлен. `include-all-providers` без провайдеров ядро не спасает — такая группа тоже
получает `REJECT`.

Вместо молчаливого пустого списка приложение показывает **причину**, выведенную из
`subscription-userinfo` (он в таких ответах настоящий):

| Что в данных подписки | Что видит пользователь | Кнопки |
| --- | --- | --- |
| `expire` в прошлом | «Подписка истекла» | «Продлить» (`clod-renew-url`), «Поддержка» |
| израсходован `total` | «Трафик закончился» + дата сброса из `subscription-refill-date` | «Докупить» (`clod-topup-url`), «Продлить», «Поддержка» |
| срок и трафик в порядке | «Провайдер не выдал серверы» + цитата имён заглушек | «Поддержка», «Обновить подписку» |

Имена заглушек используются **только как цитата** («Панель сообщает: …») — логика на них не
строится. Кнопки, как и везде, появляются только при наличии соответствующего заголовка.

Последняя строка таблицы требует подтверждения со стороны конфига: «Провайдер не выдал
серверы» показывается, только если после чистки не осталось ни одного узла **и** заглушки
там действительно были. Шаблон, в котором просто нет групп, на провайдера не списывается.
«Продлить» в этой строке не предлагается: подписка жива, продлевать нечего.

## Настройка панели Remnawave

Полный гайд — **[docs/REMNAWAVE.md](./docs/REMNAWAVE.md)**: правило User-Agent,
модификация шаблона ответа MIHOMO (правила маршрутизации, группы, маркер
`# LEAVE THIS LINE!`, ключи `remnawave:`), какие ключи шаблона клиент
перезаписывает, и настройка заголовков. Коротко:

**Правило User-Agent.** Стандартные правила формата ответа (subscription response rules)
в Remnawave не знают про наш клиент. Добавьте правило с регулярным выражением
`^clodclash` и форматом **MIHOMO**, иначе панель отдаст ответ по умолчанию, а приложение
покажет ошибку «панель не распознала клиент».

**Дополнительные заголовки.** `announce`, `announce-url`, `profile-logo`, `support-url`,
`new-url`, `fallback-url`, `notify-*`, наши `clod-*` (`clod-portal-url`, `clod-promo`,
`clod-promo-url`, `clod-renew-url`, `clod-topup-url`, `clod-simple-mode`, `clod-lock-mode`)
и остальные, которых нет в стандартном наборе Remnawave, задаются через
`customResponseHeaders`. Значения с не-ASCII текстом надёжнее отдавать в виде
`base64:<payload>`; все ссылки — только `https://`.

**Лимит устройств.** При включённом лимите панель не отдаёт подписку без `x-hwid`.
Клиент шлёт его по умолчанию, а идентификатор стабилен между перезапусками и
обновлениями приложения — устройство не будет регистрироваться заново.

**Шаблон не управляет клиентом.** `mode`, порты, `tun`, `external-controller` из
шаблона перезаписываются настройками приложения; `profile.store-selected`
принудительно `true` — выбор сервера переживает обновления подписки.

## Отчёт для поддержки

Настройки → Расширенные → **«Отчёт для поддержки»**, и та же кнопка появляется под текстом
любой ошибки. В буфер обмена кладётся готовый текст:

* версия приложения, система, устройство, режим работы ядра;
* настройки, влияющие на подключение: ядро и его канал, TUN, что дёргает Connect,
  идентификация устройства, порт, уровень логов;
* состояние подписки: имя, трафик и срок из `subscription-userinfo`, состояние HWID, какие
  заголовки провайдер прислал, использовался ли запасной адрес;
* что фильтр заглушек выбросил в последний раз;
* хвосты лога приложения и лога ядра (по 800 строк, с учётом ротации).

**Строк ядра о соединениях в отчёте нет.** mihomo на своём обычном уровне пишет строку на
каждое соединение вместе с адресом назначения (`[TCP] … --> example.com:443 match …`), а на
подробном — ещё и каждый DNS-запрос. Сырой хвост такого лога — это история посещений, и
отдавать её в чат поддержки нельзя, поэтому такие строки в отчёт не попадают вовсе;
сколько их выброшено, написано в самом отчёте. Всё остальное — старт ядра, разбор конфига,
ошибки провайдеров — остаётся.

**Секреты в нём уже замаскированы.** От любого адреса — с любой схемой, не только `http`,
и включая `vless://`, `ss://` и ссылки внутри deep-link — остаётся только схема и хост:
путь, запрос и `user:pass@` уходят под `***`. Значение после `secret`, `token`, `password`,
`passwd`, `uuid`, `authorization`, `api-key`, `x-hwid`, `hwid`, `sub-url` заменяется на
`***` (список не исчерпывающий и будет пополняться) — в том числе когда ключ и значение
слиплись, как в JSON. То же с тем, что стоит после `Bearer`, `Basic` и `Token`. Отдельно
вырезается любое «слово» от 20 символов из алфавита `A–Z a–z 0–9 - _ = . + /`, если в нём
есть цифра или разный регистр, и любой hex от 16 знаков. Домашний каталог заменяется на
`~`, чтобы в отчёт не попало имя пользователя из пути. Это осознанно грубо: лучше замазать
лишнее, чем отдать в чат токен подписки.

Что в отчёте **остаётся намеренно**: домен провайдера (без него отчёт бесполезен), версии,
настройки подключения и состояние подписки в цифрах.

Отчёт полезен ровно настолько, насколько подробен лог, который в него попал, поэтому
на новых установках уровень логов приложения — `debug` (в уже настроенном приложении
остаётся тот, что стоял). Ротация ограничивает это 1 МБ на файл и восемью файлами;
уровень меняется в Настройки → Основные → «Расширенные настройки».

## Идентификатор устройства

Считается из машинного идентификатора операционной системы:

| Система | Источник |
| --- | --- |
| Windows | `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` |
| macOS | `IOPlatformUUID` |
| Linux | `/etc/machine-id`, при отсутствии — `/var/lib/dbus/machine-id` |

Значение солится и хешируется SHA-256, наружу уходят первые 32 hex-символа.
**Сам машинный идентификатор устройство не покидает**, имя компьютера (hostname)
не отправляется вовсе. Результат подходит под проверку
Remnawave 2.9 (`^[a-zA-Z0-9=-]{10,64}$`) и кэшируется в конфигурации приложения, чтобы
не измениться при обновлении. Если стабильный источник недоступен, генерируется
случайный идентификатор и тоже кэшируется.

Идентификатор отправляется **только** на адрес подписки — больше никуда.
Выключается переключателем **«Идентификация устройства»** в настройках, в разделе
«Основные». В подсказке рядом с ним видно ровно те значения, которые уходят в панель:
`x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model` и `User-Agent`. Выключенная
идентификация убирает все четыре `x-*` разом; `User-Agent` отправляется всегда — по нему
панель отличает наш клиент и выбирает формат ответа. Панель с включённым лимитом
устройств в этом случае может отказать в выдаче подписки — тогда приложение покажет
диалог с предложением включить идентификацию обратно.

## Сборка

```bash
pnpm install
pnpm prebuild          # скачивает ядро Mihomo и служебные бинарники
pnpm dev               # запуск в режиме разработки
pnpm build             # сборка установщика
```

Требуется Rust (версия закреплена в `rust-toolchain.toml`), Node.js 22+ и pnpm.
Системные зависимости Tauri — по [инструкции Tauri](https://tauri.app/start/prerequisites/).

Проверки перед коммитом:

```bash
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml
pnpm exec tsc --noEmit
```
