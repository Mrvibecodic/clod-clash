Полный гайд с примерами шаблона и чек-листом — в репозитории:
**[docs/REMNAWAVE.md](https://github.com/Mrvibecodic/clod-clash/blob/main/docs/REMNAWAVE.md)**.
Здесь — минимум, без которого клиент не заработает.

## 1. Правило User-Agent

В **Subscription response rules** добавьте правило с регулярным выражением
`^ClodClash` (или без учёта регистра — `caseSensitive: false`, как в примере ниже) и
форматом **MIHOMO**. Без него панель отдаст ответ по умолчанию, и клиент
подписку не примет (на список ссылок в base64 он покажет «Панель прислала список
ссылок вместо конфигурации — она не узнала клиент»).

Клиент представляется как `ClodClash/<версия>`, версия бывает с суффиксом
(`0.1.11-alpha.3`) — поэтому ловите префикс, а не точную строку. Чтобы описания серверов
(`serverDescription`) доходили до него, добавьте `^ClodClash/` в
`responseModifications.additionalExtendedClientsRegex` того же правила —
именно по префиксу, а не точной строкой, иначе правило отвалится при
следующем обновлении клиента.

```json
{
  "name": "Mihomo Clients",
  "description": "Response with generated YAML config (Mihomo Template)",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    {
      "headerName": "user-agent",
      "operator": "REGEX",
      "value": "^(?:FlClash|FlClashX|Flowvy|[Cc]lash-[Vv]erge|[Kk]oala-[Cc]lash|[Cc]lash-?[Mm]eta|[Mm]urge|[Cc]lashX [Mm]eta|[Mm]ihomo|[Cc]lash-nyanpasu|clash.meta|prizrak-box|[Cc]lod[Cc]lash)",
      "caseSensitive": false
    }
  ],
  "responseType": "MIHOMO",
  "responseModifications": {
    "additionalExtendedClientsRegex": [
      "^ClodClash/"
    ]
  }
}
```

## 2. Шаблон MIHOMO

В шаблоне ответа MIHOMO должен остаться маркер `# LEAVE THIS LINE!` в основной
группе, а у `rule-providers` указан `proxy:` на основную группу.

Клиент всегда задаёт сам `external-controller`, `secret`, `socks-port`, `port`,
`redir-port` (Linux и macOS) и `tproxy-port` (Linux); `external-ui*` из шаблона
выбрасываются. `mode`, `mixed-port`, `log-level` и `unified-delay` берутся из
шаблона, пока пользователь не выбрал своё (без ключа в шаблоне — `rule`, `7897`,
`info`, `true`); закрепить режим можно заголовком `clod-lock-mode`. `ipv6` — из
шаблона, без ключа выключен. Правила, группы, `sniffer` отдаются шаблону целиком;
`dns` — пока пользователь не включил «Переопределение настроек DNS», `hosts` — пока
он не задал там свои.
Если `profile-update-interval` ни разу не приходил, подписка по расписанию не обновляется;
остановить автообновление — `profile-update-interval: 0`.

<Callout type="warn">
На Windows стеки TUN `system` и `mixed` из шаблона не берутся — только явным
выбором пользователя в диалоге TUN. На macOS и Linux стек из шаблона действует.
</Callout>

## 3. Заголовки

Название тарифа, логотип, объявление, ссылки на кабинет и поддержку, лимит
устройств, режимы интерфейса — всё это панель передаёт заголовками ответа.
Полный справочник — на страницах [Заголовки](/docs/providers/headers) и
[Заголовки clod-*](/docs/providers/clod-headers).

## 4. Защищённый канал и отчёты

Клиент сам пробует защищённый канал прослойки
[remnawave-subscription-middleware](https://github.com/Mrvibecodic/remnawave-subscription-middleware),
когда пользователь добавляет подписку; без канала у провайдера подписка
загружается обычным способом. Подписка с каналом после планового обновления
(если обновления реже раза в 6 часов — и между ними, не чаще раза в 6 часов)
шлёт отчёт о качестве узлов: пинги и итоги 16–20 по узлам, трафик, вид сети и
внешний адрес, с которого делались замеры. Принимает и показывает отчёты
прослойка (вкладка Clod Clash → «Статистика»), если в ней включён приём; включён
ли он, клиент узнаёт из ответа подписки по каналу (об этом сообщают свежие
версии прослойки) и при выключенном замеров не копит.

Внешний адрес и идентификатор устройства, связанные с подпиской, могут быть
персональными данными по 152-ФЗ и GDPR, и их оператор — провайдер, а не авторы клиента. Включая
приём отчётов или проверку 16–20, опишите это в своей политике конфиденциальности
(цели, основание, сроки хранения, получатели) и известите пользователей. Что
именно отправляет клиент — в
[политике конфиденциальности клиента](https://github.com/Mrvibecodic/clod-clash/blob/main/PRIVACY_POLICY.ru.md).

Адрес замеров клиент узнаёт у Яндекса. В режиме TUN этот запрос идёт по
правилам шаблона, поэтому добавьте оба адреса в `DIRECT` выше остальных правил —
иначе в отчёт попадёт адрес выхода сервера, а не пользователя:

```yaml
rules:
  - DOMAIN,ipv4-internet.yandex.net,DIRECT
  - DOMAIN,ipv6-internet.yandex.net,DIRECT
  # … остальные правила
```

## 5. Лимит устройств

При включённом лимите панель не отдаёт подписку без `x-hwid`. Клиент шлёт его
по умолчанию, идентификатор стабилен между обновлениями — устройство не будет
регистрироваться заново.

При успешном ответе (2xx) с `x-hwid-max-devices-reached`, `x-hwid-limit` или
`x-hwid-not-supported` клиент убирает прежние серверы этой подписки (даже если
заглушки в панели выключены), а другие маршруты и запасной адрес не перебирает.
Ответ с кодом ошибки — обычная неудача обновления, прежние серверы остаются.
