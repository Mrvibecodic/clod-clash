Полный гайд с примерами шаблона и чек-листом — в репозитории:
**[docs/REMNAWAVE.md](https://github.com/Mrvibecodic/clod-clash/blob/main/docs/REMNAWAVE.md)**.
Здесь — минимум, без которого клиент не заработает.

## 1. Правило User-Agent

В **Subscription response rules** добавьте правило с регулярным выражением
`^clodclash` и форматом **MIHOMO**. Без него панель отдаст ответ по умолчанию,
а клиент покажет «панель не распознала клиент».

Клиент представляется как `ClodClash/<версия>`. Чтобы описания серверов
(`serverDescription`) доходили до него, добавьте `^ClodClash/` в
`additionalExtendedClientsRegex` — именно по префиксу, а не точной строкой,
иначе правило отвалится при следующем обновлении клиента.

## 2. Шаблон MIHOMO

В шаблоне ответа MIHOMO должен остаться маркер `# LEAVE THIS LINE!` в основной
группе, а у `rule-providers` указан `proxy:` на основную группу. Режим
маршрутизации, порты и `external-controller` из шаблона клиент перезаписывает;
правила, группы, `dns`, `hosts`, `sniffer` — отдаёт шаблону целиком.

<Callout type="warn">
Стек TUN из шаблона на Windows принимается только `gvisor`. `system` и `mixed`
там включаются лишь явным выбором пользователя.
</Callout>

## 3. Заголовки

Название тарифа, логотип, объявление, ссылки на кабинет и поддержку, лимит
устройств, режимы интерфейса — всё это панель передаёт заголовками ответа.
Полный справочник — на странице [Заголовки](/docs/providers/headers).

## 4. Лимит устройств

При включённом лимите панель не отдаёт подписку без `x-hwid`. Клиент шлёт его
по умолчанию, идентификатор стабилен между обновлениями — устройство не будет
регистрироваться заново.
