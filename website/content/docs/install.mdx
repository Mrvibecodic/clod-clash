Все сборки собраны на **[странице загрузки](/download)** — там же размеры файлов и
постоянные ссылки вида `/releases/latest/download/<файл>`, которые всегда ведут на
последнюю обычную версию.

## Windows

Скачайте установщик `.exe` (x64) и запустите его. Установщик просит права
администратора — он ставит приложение и фоновую службу, которая нужна для режима
TUN. Отдельного запроса прав ради службы не будет ни при включении TUN, ни при
обновлении: служба обновляется вместе с приложением.

Заодно установщик добавляет правила брандмауэра Windows для обоих ядер — без него
стеки `system` и `mixed` в TUN не пропускают трафик. Подробнее —
в разделе [Подключение](/docs/connection#tun-на-windows).

<Callout type="warn">
Сборки пока не подписаны сертификатом, поэтому SmartScreen может показать
предупреждение «Неизвестный издатель». Нажмите «Подробнее» → «Выполнить в любом
случае».
</Callout>

### Портативная сборка

`Clod.Clash_x64_portable.zip` работает без установки: распакуйте и запустите.
Фоновая служба для TUN при этом не ставится — права приложение попросит при
включении TUN. Обновления в фоне портативная сборка не скачивает: новую версию
берите со [страницы загрузки](/download).

## macOS

Скачайте `.dmg` под свой процессор: **Apple Silicon** (`aarch64`) или
**Intel** (`x64`), перетащите приложение в «Программы». Нужна macOS 11 или
новее.

<Callout type="warn">
Сборки не подписаны сертификатом Apple, поэтому при первом запуске macOS
скажет, что не может проверить приложение. Откройте **Системные настройки →
Конфиденциальность и безопасность**, внизу нажмите «Всё равно открыть» и
подтвердите паролем. Это нужно один раз: обновления приложение ставит само,
без этого окна. На macOS 15 и новее пункт «Открыть» в контекстном меню
больше не помогает — только через настройки.
</Callout>

Если macOS пишет, что приложение повреждено и его нужно переместить в
Корзину (так на Apple Silicon открываются сборки по 0.1.11-alpha.2
включительно), снимите с него отметку о загрузке из интернета:

```bash
xattr -dr com.apple.quarantine "/Applications/Clod Clash.app"
```

Режим TUN на macOS при первом включении спросит пароль администратора —
один раз, чтобы поставить фоновую службу.

### Установка одной командой

Вставьте в «Терминал»:

```bash
curl -fsSL https://mrvibecodic.github.io/clod-clash/install-macos.sh | bash
```

Скрипт сам выберет сборку под процессор, скачает последнюю обычную версию
с GitHub, поставит её в «Программы» и запустит. Файл, скачанный из
терминала, macOS не отмечает как загруженный из интернета, поэтому окна
проверки не будет.

### Как работает скрипт

Скрипт короткий, его можно прочитать до запуска: откройте адрес в браузере
или выполните `curl -fsSL https://mrvibecodic.github.io/clod-clash/install-macos.sh | less`.
По шагам он:

1. Проверяет, что это macOS, и выбирает `Clod.Clash_aarch64.dmg` для
   Apple Silicon или `Clod.Clash_x64.dmg` для Intel. Процессор определяется
   верно и в терминале, запущенном через Rosetta.
2. Если Clod Clash запущен, останавливается и просит закрыть приложение.
3. Скачивает `.dmg` последней обычной версии во временную папку по той же
   постоянной ссылке с GitHub, что и на странице загрузки.
4. Подключает образ только для чтения, без значка в Finder, и копирует из
   него приложение во временную папку.
5. Заменяет `/Applications/Clod Clash.app` скопированным. Пароль
   администратора спрашивается, только если у вашей учётной записи нет
   права записи в «Программы». Если скачивание или копирование сорвалось,
   прежняя версия остаётся на месте.
6. Отключает образ, удаляет временные файлы и запускает приложение.

Скрипт не меняет настройки безопасности macOS и не трогает другие
приложения. Фоновую службу для TUN он не ставит — её приложение ставит само
при первом включении TUN. Настройки и подписки хранятся отдельно от
приложения, поэтому повторный запуск скрипта просто ставит свежую версию
поверх. Предварительные версии скрипт не ставит, они приходят через
обновление в самом приложении.

## Linux

Доступны пакеты `.deb` (Debian, Ubuntu, Mint) и `.rpm` (Fedora, openSUSE) для
x86_64:

```bash
sudo apt install ./Clod.Clash_amd64.deb
# или
sudo dnf install ./Clod.Clash-x86_64.rpm
```

На системах с systemd пакет сразу регистрирует фоновую службу для TUN, поэтому пароль при
включении TUN обычно не спрашивается. Если служба всё же не отвечает, приложение
попросит права через `pkexec` (polkit) — он должен быть установлен.

## Обновления

Приложение проверяет обновления само и предлагает установить новую версию —
скачивание идёт в фоне, установка по нажатию. Проверить вручную можно в
**Настройки → Основные**: значок шестерёнки в строке «Версия Clod» («Проверить
обновления»); если прямой путь до GitHub закрыт, проверка повторяется через
собственный прокси.

Там же переключатель **«Предварительные сборки»** (по умолчанию выключен): с ним
приходят альфа- и бета-сборки, без него — только стабильные релизы.
Автоматическую проверку можно выключить в **Продвинутые настройки → Оформление
и поведение → Прочее → «Автоматическая проверка обновлений»**.

## Ядро

В каждой сборке два ядра, переключаются в **Настройки → Продвинутые настройки →
Настройки Clash → «Ядро Clash»**:

- **Mihomo** (по умолчанию) — последний стабильный релиз MetaCubeX без изменений.
- **[Clod Core](https://github.com/Mrvibecodic/clod-core)** — наш форк Mihomo. Собран на
  свежей ветке Alpha и отличается тремя вещами:
  - **Новая библиотека TLS-отпечатков** — utls v1.9.0-mod-meta от MetaCubeX вместо
    v1.8.7: отпечатки Firefox 148 и Safari 26.3 с постквантовым ключом и исправления
    возобновления TLS-сессий. Отпечатки chrome, ios и edge не меняются.
  - **Узлы не «мигают» мёртвыми.** При автоматической проверке узлов (во всех группах и у
    провайдеров узлов) узел, у которого проверка зависла или оборвалась, проверяется второй раз
    через секунду, и мёртвым он считается, только если не ответил и тогда. Закрытый порт или не
    тот код ответа — узел мёртв сразу, в том числе на Windows. Ручной тест задержки работает как
    раньше.
  - **Нестабильный узел проигрывает стабильному.** Провалы проверок остаются в истории
    узла, и автовыбор (url-test) добавляет к его задержке штраф — четверть тайм-аута за
    каждый провал в трёх последних пробах. Провалы автоматических проверок пишутся в журнал
    ядра с уровнем warning.

**Обновление ядра.** Кнопка «Обновить» там же: ядро само скачивает свежую версию
из своих релизов (Clod Core — с clod-core, Mihomo — с MetaCubeX) и подменяет файл.
На Windows это работает, только когда ядро запущено через службу, иначе кнопка
покажет подсказку.

**«Управляемое ядро (самообновление)»** — другой способ: стоковое Mihomo нужного
канала («Стабильный» или «Альфа»), которое работает без службы. Пока оно включено
и ядро запущено без службы, оно заменяет выбранное ядро.
