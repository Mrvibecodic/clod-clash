# Настройка Remnawave под Clod Clash

Пошагово: как заставить панель отдавать клиенту правильный формат, как
модифицировать шаблон ответа (правила, группы, DNS) и какие ключи шаблона
клиент перезапишет в любом случае.

Термины панели: **Subscription response rules** — выбор формата ответа по
`User-Agent`; **Subscription templates** — сами шаблоны форматов (нам нужен
**MIHOMO**); **customResponseHeaders** — дополнительные заголовки ответа
(раздел настроек подписки).

---

## 1. Правило User-Agent (обязательно)

Клиент представляется как `ClodClash/<версия приложения>` — например, `ClodClash/1.2.3`.
Стандартные правила Remnawave про него не знают, поэтому без своего правила
панель отдаст ответ по умолчанию, а приложение покажет ошибку «панель не
распознала клиент».

В **Subscription response rules** добавьте правило:

| Поле | Значение |
| --- | --- |
| Регулярное выражение | `^clodclash` |
| Формат ответа | **MIHOMO** |

Сопоставление регистронезависимое. Регулярка «с начала строки» — так посторонний
клиент со словом `clodclash` в середине UA не получит ваш шаблон случайно.

## 2. Шаблон MIHOMO: как он устроен

Шаблон редактируется в **Subscription templates → MIHOMO**. Это обычный
YAML-конфиг mihomo, в который панель при каждом запросе подставляет узлы
пользователя. Точка подстановки — строка-маркер внутри `proxies:` группы:

```yaml
proxy-groups:
  - name: "🌍 Все в прокси кроме RU"
    type: url-test
    url: "http://www.gstatic.com/generate_204"
    interval: 25
    proxies:
      - "🇩🇪 Автовыбор Германия"
      # LEAVE THIS LINE!        # ← сюда панель вставит узлы подписки
```

Маркер `# LEAVE THIS LINE!` удалять нельзя — без него узлы в группу не попадут.

Расширения Remnawave задаются вложенным ключом `remnawave:` у группы:

```yaml
  - name: "🇩🇪 Автовыбор Германия"
    hidden: true                # группу не видно в списке клиента
    type: url-test
    include-all: true
    filter: 'Германия'          # берём только узлы с «Германия» в имени
    exclude-filter: 'моя'       # ...кроме этих
    remnawave:
      include-proxies: false    # НЕ добавлять сюда все узлы автоматически
    proxies: []
```

Полезные ключи `remnawave:` (по [официальной документации](https://docs.rw/guides/templates/mihomo/)):

| Ключ | Где | Что делает |
| --- | --- | --- |
| `include-proxies: false` | proxy-groups | не добавлять в группу все узлы — только то, что перечислено руками или маркером |
| `include-proxies: true` | proxy-providers | добавлять узлы автоматически при построении цепочек |
| `select-random-proxy: true` | proxy-groups | добавить один случайный узел пользователя |
| `shuffle-proxies-order: true` | proxy-groups | перемешать узлы пользователя в группе |

Обычные ключи mihomo (`hidden`, `filter`, `exclude-filter`, `include-all`,
`interval`, `tolerance`, `lazy`) работают как в mihomo — клиент их уважает:
скрытые группы не показываются, порядок групп шаблона сохраняется в чипах
выбора сервера.

## 3. Как модифицировать правила маршрутизации

Правила — это обычные `rules:` + `rule-providers:` mihomo внутри того же
шаблона. Несколько практических замечаний:

* **`rule-providers` качаются клиентом**, не панелью. Указывайте у каждого
  провайдера `proxy: "<имя вашей основной группы>"` — иначе на заблокированных
  сетях списки не скачаются и правила молча не применятся.
* **Порядок правил важен**: mihomo идёт сверху вниз до первого совпадения.
  Типовой порядок: точечные DOMAIN-правила → DIRECT-исключения (торренты,
  ru-сервисы, игры) → сервисные группы (YouTube, соцсети) → гео-списки RU в
  DIRECT → `MATCH` в основную группу последним.
* **`RULE-SET,...,DIRECT` для гео-RU** — причина того, что «спидтест идёт с
  родного IP» в режиме «По правилам»: ближайший сервер speedtest находится в RU и
  попадает под `geoip-ru → DIRECT`. Это не ошибка клиента — так написан шаблон.
  Нужен спидтест через прокси — переключите режим «Глобальный» в настройках
  клиента или уберите соответствующее правило из шаблона.
* Изменения шаблона доезжают до клиентов при следующем обновлении подписки
  (вручную или по `profile-update-interval`).

## 4. Граница ответственности: что ваше, что клиента

Конфиг, который в итоге получает ядро, собирается из трёх источников: шаблон
подписки, настройки приложения и его же встроенные умолчания. Часть ключей
клиент считает своей зоной и перезаписывает при каждой генерации, часть отдана
шаблону целиком, а секция `tun` поделена между вами и пользователем. Ниже —
всё это в одном месте, вместе с граблями, на которые стоит посмотреть до того,
как шаблон уедет в бой.

### 4.1 Что клиент перезапишет в любом случае

```
mixed-port, socks-port, port, redir-port, tproxy-port,
external-controller (+ unix/pipe/cors), secret,
mode, allow-lan, log-level, unified-delay,
tun.enable, tun.auto-route, tun.auto-detect-interface
```

`ipv6` — ваш: значение из шаблона доходит до ядра как есть. Переключатель
в настройках клиента отключён и только показывает действующее значение; если
шаблон ключ не задал, IPv6 выключен.

Практические следствия для автора шаблона:

* **`mode: rule` в шаблоне не «прибивает» режим.** Режим маршрутизации выбирает
  пользователь в настройках клиента (или вы — заголовком `clod-lock-mode`,
  который прячет переключатель; замок держится, пока панель его подтверждает —
  подробности в [HEADERS.md](./HEADERS.md)).
* **Чем ловить трафик — тоже заголовок.** `clod-connect-mode: tun` включает у
  клиента только туннель, `proxy` — только системный прокси, `both` — оба.
  Без заголовка кнопка «Подключить» поднимает системный прокси. Пользователь
  может выбрать сам, и его выбор важнее заголовка; на запертом профиле
  (`clod-lock-mode: 1`) решает заголовок, и оба переключателя способа
  подключения у пользователя пропадают.
* **Порты и `external-controller` из шаблона не действуют** — их задаёт
  приложение, и подставить свой порт управления ядром шаблоном нельзя.

### 4.2 Секция `tun`: три ступени

Включение туннеля и его маршрутизацию задаёт приложение, но три ключа отданы
вам. Порядок старшинства — **выбор пользователя → шаблон подписки → умолчание
клиента**:

| Ключ | Кто решает |
| --- | --- |
| `stack` | вы, если пользователь не выбрал руками; иначе он. **На Windows из шаблона принимается только `gvisor`**: `system` и `mixed` там включаются только явным выбором пользователя в диалоге TUN |
| `strict-route` | вы, если пользователь не выбрал руками; иначе он |
| `dns-hijack` | то же |
| `enable`, `auto-route`, `auto-detect-interface` | только приложение |
| `device`, `mtu`, `route-exclude-address`, `auto-redirect` | приложение, как только пользователь хоть раз сохранил диалог TUN; до этого дойдёт ваше значение |

Пользователь выбирает в диалоге «Настройки TUN»; положение **Auto** означает
«слушаться подписки». Если ключа нет ни у вас, ни в настройках, клиент ставит
своё умолчание: `stack: gvisor`, `strict-route: false`,
`dns-hijack: ["any:53"]`.

Отсюда важное: **эти три ключа правятся шаблоном, без выпуска новой версии
клиента** — и включение, и откат. И столь же важное обратное: ошибка в них
кладёт туннель у всех сразу. Что именно проверить — в 4.5.

Значения не проверяются: мусор в `stack` или `strict-route` уедет в ядро как
есть, и профиль просто не применится с уведомлением об ошибке.

Нижнюю строку таблицы лучше считать «не задавать вовсе»: у свежей установки
этих ключей в настройках приложения нет, и ваши значения дойдут до ядра, а
после первого же сохранения диалога TUN — перестанут. Поведение, которое
зависит от того, открывал ли пользователь диалог, в шаблоне не нужно.

### 4.3 Что клиент дописывает поверх вашего

* **`profile.store-selected` клиент принудительно ставит `true`** — выбор
  сервера переживает обновления подписки; прописывать его в шаблоне не нужно.
* **Под включённым TUN поднимается резолвер.** `dns.enable` становится `true`
  безусловно — с выключенным резолвером туннель перехватывает 53-й порт, и
  имена перестают разрешаться совсем. Если `enhanced-mode` это `fake-ip` или
  не задан вовсе, клиент дополнительно проставит отсутствующие
  `fake-ip-range: 198.18.0.1/16`, `dns.ipv6` по верхнему `ipv6` и
  `fake-ip-range6` при включённом IPv6. Осознанный `redir-host` не отбирается —
  подставляется только включение резолвера.
* **`bind-address`.** При `allow-lan: true` адрес привязки, оставленный на
  loopback, заменяется на `*` — иначе разрешение для локальной сети ничего не
  даёт.
* **Два встроенных скрипта** (пользователь может выключить их в настройках):
  `mode: script` приводится к `rule`, а `alpn` строкой у hysteria-узлов
  оборачивается в список.
* **Группы приводятся в порядок.** Ссылки на несуществующие узлы из
  `proxy-groups` вычищаются, а группа, оставшаяся пустой, получает `REJECT` —
  иначе ядро не примет конфиг (`` `use` or `proxies` missing ``) и пользователь
  увидит ошибку разбора вместо внятного объяснения.
* **Узлы-заглушки панели клиент выбрасывает.** Настройка Subscription settings →
  *Custom remarks* (`isShowCustomRemarks`) заставляет панель на истёкшую подписку,
  исчерпанный трафик, отключённого пользователя и ненастроенные хосты отдавать
  конфиг с фиктивными узлами `0.0.0.0:1` с нулевым `uuid` вместо серверов.
  Клод Клэш вырезает их до передачи конфига ядру — в списке серверов они не
  появятся, а опустевшая группа получает `REJECT`, иначе mihomo не примет конфиг
  (`` `use` or `proxies` missing ``) и пользователь увидит ошибку разбора вместо
  внятного объяснения. То же и когда заглушек не было вовсе, а `proxies` просто
  пустой: CLASH-шаблон панель собирает только из `trojan`/`shadowsocks`, поэтому
  vless-заглушки она отбрасывает сама. Вместо этого приложение показывает причину, выведенную из
  `subscription-userinfo`: «Подписка истекла» (срок в прошлом), «Трафик
  закончился» (израсходован `total`, дата сброса — из `subscription-refill-date`)
  или «Провайдер не выдал серверы» (срок и трафик в порядке). В последнем случае
  под текстом цитируются имена ваших заглушек — это единственное место, где они
  видны, и единственный способ подсказать пользователю, что случилось.
  **Платёжных кнопок в этих карточках нет** — в приложении их нет нигде.
  Пользователю доступны «Поддержка» (`support-url`) и «Обновить подписку»;
  единственная ссылка на оплату во всём клиенте — личный кабинет
  (`clod-portal-url`), и он живёт на главном экране, а не здесь. Последняя строка
  требует, чтобы заглушки в конфиге действительно были: шаблон, в котором просто
  нет групп, на провайдера не спишут.
* **Если вы хотите показывать свои заглушки сами — `clod-show-0hosts: 1`.**
  С этим заголовком клиент не разбирает ответ вовсе: ваши узлы попадают в список
  серверов со своими названиями, экранов «Подписка истекла» и прочих не будет.
  Тексты целиком за вами — пишите в *Custom remarks* то, что должен прочитать
  человек. Учтите две вещи. Первая: у таких узлов не будет пинга, адрес
  `0.0.0.0` никуда не отвечает. Вторая, важнее: заглушечный ответ запишется в
  конфигурацию и **затрёт рабочие серверы**, поэтому сразу после продления
  подключиться будет не к чему — до следующего успешного обновления подписки.
  Диалог лимита устройств этот заголовок не отключает: он приходит из
  `x-hwid-*`, а не из узлов, и показывается всегда.
* **Заглушечный ответ затирает прежнюю конфигурацию — во всех случаях, включая
  лимит устройств.** Это не побочный эффект: ваш ответ означает «серверов у
  этого пользователя сейчас нет», и клиент его не оспаривает. Раньше на лимите
  устройств он сохранял прежние серверы, и лишнее устройство продолжало ими
  пользоваться — то есть лимит на нём не работал. Серверы возвращает первое же
  успешное обновление подписки; кнопка «Обновить подписку» есть на самом экране
  статуса, и человеку не надо ничего искать.

### 4.4 Что отдано шаблону целиком

Всё, чего нет в 4.1. Клиент ничего не выбрасывает из профиля: любой
верхнеуровневый ключ доходит до ядра как есть. В том числе:

* `dns` и `hosts` — целиком ваши, пока пользователь не включил у себя
  переопределение DNS (по умолчанию выключено; включил — оба блока становятся
  его, и шаблон их больше не задаёт);
* `sniffer`, `find-process-mode`, `geodata-mode`, `geox-url`, `global-client-fingerprint`;
* `rules`, `rule-providers`, `proxy-groups`, `proxy-providers`;
* `listeners`, `tunnels`, `authentication`, `skip-auth-prefixes`,
  `external-ui-url`, `experimental`, `tls`;
* остальные ключи `profile` кроме `store-selected`.

Из этого следует то, о чём стоит помнить: **шаблон — доверенный код**. Он
может открыть на машине пользователя дополнительный порт (`listeners`),
завести туннель (`tunnels`) или заставить ядро скачать панель управления
(`external-ui-url`). Клиент такие ключи не фильтрует — считайте шаблон частью
своего продукта и держите доступ к нему так же, как к панели.

### 4.5 Подводные камни шаблона

* **`stack: system` и `stack: mixed` на Windows не работают при включённом
  брандмауэре.** Это [прямо написано в доке
  mihomo](https://wiki.metacubex.one/config/inbound/tun/): оба этих стека
  поднимают локальный слушатель и заворачивают в него перехваченные
  соединения, а входящие подключения к процессу ядра Defender режет — трафика
  просто нет, и в логе при этом ни одной ошибки. Разрешать ядро надо руками
  (Параметры → Центр безопасности Windows → Разрешить приложение через
  брандмауэр → выбрать ядро), поэтому **для шаблона, который увидят обычные
  пользователи Windows, безопасен только `gvisor`** — он сокет не слушает и
  ничего не требует. На macOS брандмауэр по умолчанию пропускает подписанное
  ПО, на Linux не мешает вовсе. Поэтому клиент на Windows `system` и `mixed`
  из шаблона не берёт вовсе: там они включаются только руками в диалоге TUN,
  а шаблонное значение действует на macOS и Linux.
* **`strict-route: true` на Windows режет не только утечки.** Он добавляет
  правила брандмауэра против multihoming-резолвинга Windows, но той же рукой
  ломает часть приложений с виртуальными адаптерами.
* **`fake-ip-range` задаёт адрес самого TUN-устройства.** Ядро берёт базовый
  адрес диапазона и делает из него `/30`. Держите привычный вид `x.x.x.1/16`
  (например `198.18.0.1/16`): адрес, у которого последний октет даёт остаток 3
  при делении на 4, не оставляет ядру соседнего адреса, и стеки `system` и
  `mixed` не стартуют вовсе (`need one more IPv4 address in first prefix`).
* **Локальную сеть исключайте правилами внутри туннеля, а не
  `route-exclude-address`.** Исключение вида `192.168.0.0/16` уводит мимо
  туннеля и запросы к DNS роутера — `dns-hijack` не срабатывает, и fake-ip
  рассыпается у всех, у кого DNS выдаёт роутер. Правило
  `GEOIP,private,DIRECT` (и `IP-CIDR` на нужные подсети) делает то же самое, но
  внутри туннеля и без побочных эффектов.
* **Ядро — стабильное.** Сборка берёт последний стабильный релиз mihomo, а не
  Alpha-ветку; ключи, которых в стабильной ветке ещё нет, приведут к отказу
  применить профиль. Пользователь может переключиться на альфа-ядро сам, но
  рассчитывать на это в боевом шаблоне нельзя.
* **Маркер `# LEAVE THIS LINE!`** обязателен в основной группе, иначе узлы
  подписки в неё не попадут (см. раздел 2).

## 5. Заголовки ответа (customResponseHeaders)

Полный список заголовков, которые клиент понимает, — в [README](../README.md#заголовки-подписки).
Кратко о правилах:

* Всё, чего нет в стандартном наборе Remnawave (`announce`, `clod-*`,
  `notify-*`, `fallback-*` и т.д.), задаётся через **customResponseHeaders**.
* Не-ASCII значения (кириллица, эмодзи, переводы строк) надёжнее отдавать как
  `base64:<payload>`.
* **Все ссылки — только `https://`.** `http://` в любом URL-заголовке
  (`profile-logo`, `announce-url`, `support-url`, `clod-portal-url`,
  `clod-bot-url`, `clod-monitor-url`, `clod-guide-url`, `clod-promo-url`,
  `profile-web-page-url`) клиент отбрасывает как небезопасный.
  Для `support-url` и `clod-bot-url` дополнительно допустимы схемы `tg:` и
  `mailto:` — но и там `http://` не принимается: обычная ссылка обязана быть
  `https://`.

### Ссылки провайдера

Пять заголовков собираются в одну строку на главном экране, подписанную именем
подписки, и повторяются отдельной группой в настройках клиента:

| Заголовок | Кнопка | Схемы |
| --- | --- | --- |
| `clod-portal-url` | Кабинет | `https` |
| `support-url` | Поддержка | `https`, `tg:`, `mailto:` |
| `clod-bot-url` | Бот | `https`, `tg:`, `mailto:` |
| `clod-monitor-url` | Мониторинг | `https` |
| `clod-guide-url` | Инструкция | `https` |

Бот заведён отдельно от поддержки намеренно: он выдаёт ссылку, продлевает и
отвечает сам, а «Поддержка» — живой человек, и путать эти две кнопки не стоит.
Показываются только те ссылки, которые вы прислали; пропал заголовок — пропала
и кнопка, а если не прислано ни одной, строки нет вовсе. Ссылки принадлежат
конкретной подписке: у пользователя с несколькими подписками они не смешиваются.

### Цвет в объявлениях

`announce` и `clod-promo` понимают подсветку слов: код `#RRGGBB` пишется вплотную
к слову, без пробела.

```json
{
  "announce": "rwEncodeBase64:#EF4444ВАЖНО: узел #F59E0BНидерланды на профилактике до 05:00"
}
```

Красится одно слово — до ближайшего пробела. Сам код в лимит 500 символов не входит,
так что подсветка не съедает текст объявления. Код с пробелом после него (`#EF4444 ВАЖНО`)
и невалидный hex остаются обычным текстом. После решётки читаются ровно шесть знаков:
в `#1234567` цветом `#123456` покрасится оставшаяся `7`. Два покрашенных слова подряд
разделяйте пробелом (`#EF4444раз #00FF00два`) — иначе второй код попадёт внутрь первого
слова и покажется текстом. Цвет применяется как прислали — и в светлой,
и в тёмной теме, поэтому выбирайте оттенки, читаемые на обоих фонах.

## 6. Идентификация устройств (HWID)

С каждым запросом подписки клиент шлёт:

| Заголовок | Пример |
| --- | --- |
| `User-Agent` | `ClodClash/<версия приложения>` — панель видит клиент и его версию в списке устройств |
| `x-hwid` | стабильный анонимный идентификатор (32 hex) |
| `x-device-os` | `Windows` / `macOS` / `Linux` |
| `x-ver-os` | `24H2` / `15.5` / `Ubuntu 24.04` |
| `x-device-model` | `Windows 11 Pro` / `MacBookPro18,3 (M1 Pro)` / `Ubuntu 24.04.1 LTS` |

Формат совпадает с koala-clash, так что включённый в панели лимит устройств
работает из коробки. Имя компьютера пользователя (hostname) клиент **не**
отправляет.

Идентификация включена по умолчанию, но пользователь может выключить её
переключателем «Идентификация устройства» (Настройки → Основные). Тогда все
четыре заголовка `x-*` пропадают разом — `User-Agent` остаётся, поэтому правило
`^clodclash` продолжает срабатывать. Панель с лимитом устройств такой запрос
отклонит; чтобы приложение показало пользователю понятный диалог, отвечайте
заголовком `x-hwid-not-supported: true`. Он важнее `x-hwid-limit`, который панель
в этой ветке ставит заодно: клиент покажет «включите идентификацию», а не «лимит
устройств исчерпан».

**Свой текст в диалоге устройства.** Оба диалога — «Достигнут лимит устройств» и
«Требуется идентификация устройства» — показывают текст из необязательного
заголовка `clod-hwid-limit` (обычный текст или `base64:<payload>`, до 500
символов, та же подсветка `#RRGGBB`, что и у объявлений). Это отдельный
заголовок, а не `announce`: объявление на главной видят все, а здесь нужно
объяснение для одного заблокированного устройства — например, где отвязать
старое. Без заголовка диалог обходится своим текстом.

Состояние устройства видно и после закрытия диалога: пока панель отвечает
`x-hwid-limit` или `x-hwid-not-supported`, на карточке подписки красной строкой
написано, почему она не обновляется.

## 7. Описание сервера в списке (необязательно)

У каждого хоста в панели есть поле **Server description** — до 30 символов,
которые видит пользователь. Clod Clash показывает их в списке серверов подписью
под именем: «10 Гбит · без лимита», «Netflix, Disney+», «резервный, бывает
медленным». Где описания нет, строка выглядит как раньше.

Само по себе поле до клиента не доедет: панель отдаёт его только «расширенным
клиентам» и узнаёт их по `User-Agent` собственным списком, в котором нас нет.
Чтобы описания приходили, добавьте в **Subscription response rules** — в то же
правило, где выбран формат MIHOMO, — модификацию:

```json
"additionalExtendedClientsRegex": ["^ClodClash/"]
```

Проверка: запросите ссылку подписки с заголовком `User-Agent: ClodClash/0.0.1` —
у узлов должно появиться поле `serverDescription` рядом с `name` и `server`:

```yaml
proxies:
  - name: "🇳🇱 Netherlands 01"
    type: vless
    server: nl-01.example.com
    serverDescription: "10 Гбит · без лимита"
```

Описание переопределяется для отдельного External Squad
(`hostOverrides.serverDescription`) — так разные тарифы увидят на одном хосте
разный текст.

## 8. Чек-лист

1. Добавлено правило `^clodclash` → **MIHOMO** в Subscription response rules.
2. В шаблоне MIHOMO на месте маркер `# LEAVE THIS LINE!` в основной группе.
3. У `rule-providers` указан `proxy:` на основную группу.
4. Ссылки в заголовках — только `https://`; кириллица — через `base64:`.
5. Не полагаетесь на `mode`, порты и `external-controller` из шаблона — их
   задаёт клиент (раздел 4.1).
6. Если в шаблоне есть `tun.stack` — помните, что на Windows клиент примет из
   него только `gvisor`; `system`/`mixed` подействуют на macOS и Linux
   (раздел 4.2 и 4.5).
7. Локальная сеть исключена правилами внутри туннеля, а не
   `route-exclude-address`.
8. При включённом лимите устройств проверено, что клиент регистрируется
   (`x-hwid-active: true` в ответе).
9. Если нужны описания серверов — в правиле есть
   `additionalExtendedClientsRegex: ["^ClodClash/"]`, а у хостов заполнено
   **Server description**.
