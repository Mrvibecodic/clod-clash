# Выпуск релиза Clod Clash

Как собрать и опубликовать версию, которую установленные клиенты подхватят
через встроенный апдейтер.

## Как это работает

`tauri.conf.json` указывает апдейтеру два эндпоинта (пробуются по порядку):

```
https://github.com/Mrvibecodic/clod-clash/releases/download/updater/latest.json
https://github.com/Mrvibecodic/clod-clash/releases/latest/download/latest.json
```

Первый — «плавающий» релиз с тегом `updater`, куда после публикации версии
копируется её `latest.json`. Он нужен потому, что GitHub не считает
pre-release'ы «latest»: пока версии выходят как pre-release, второй эндпоинт
пуст, и обновления едут только через тег `updater`. Когда выйдет первый
стабильный релиз, заработает и второй эндпоинт как резервный.

Workflow `.github/workflows/release-clod.yml` по тегу `clod-v{версия}` собирает
инсталлеры (Windows x64/arm64, macOS arm64/x64, Linux x64), подписывает
артефакты апдейтера и прикладывает `latest.json` к черновику релиза. После
публикации релиз становится `latest`, и приложение видит обновление: молчаливый
апдейтер (`SilentUpdater`) проверяет при старте и раз в сутки, скачивает в кэш
и предлагает установить при следующем запуске. Если GitHub недоступен напрямую,
проверка и скачивание повторяются через собственное ядро (mixed-port).

## Один раз перед первым релизом

1. **Сгенерировать ключи подписи апдейтера** (на своей машине):

   ```bash
   pnpm tauri signer generate -w ~/.tauri/clodclash.key
   ```

   Команда выведет приватный ключ (файл) и публичный ключ (строка base64).

2. **Публичный ключ** вставить в `src-tauri/tauri.conf.json` →
   `plugins.updater.pubkey` (сейчас там ещё ключ апстрима — с ним наши
   артефакты не пройдут проверку подписи).

3. **Приватный ключ** положить в секреты репозитория GitHub
   (Settings → Secrets and variables → Actions):
   - `TAURI_PRIVATE_KEY` — содержимое файла ключа;
   - `TAURI_KEY_PASSWORD` — пароль (если задавали; иначе создать пустым).

   Приватный ключ никогда не коммитится.

## Каждый релиз

1. Поднять версию в `package.json` и `src-tauri/tauri.conf.json`
   (`Cargo.toml` подтянет из tauri.conf при сборке; проверить `pnpm i` /
   lock-файл при необходимости).
2. Закоммитить, затем создать и запушить тег:

   ```bash
   git tag clod-v0.0.2
   git push origin main clod-v0.0.2
   ```

3. Дождаться workflow «Release Clod Clash» → в Releases появится **черновик**
   с инсталлерами, `*.sig` и `latest.json`.
4. Проверить черновик (скачать, поставить, убедиться что приложение
   запускается), заполнить changelog и **опубликовать** релиз.
5. После публикации скопировать `latest.json` опубликованного релиза в
   плавающий релиз с тегом `updater` (создать при первом разе; далее —
   заменять ассет `latest.json`). Именно с этого момента установленные
   клиенты видят новую версию — при старте или в течение суток.
   Неподписанный или подписанный чужим ключом артефакт апдейтер отвергает.
6. Пока проект в альфе, публиковать релизы с галкой **pre-release**.

## Заметки

- Расписание апстримного `autobuild.yml` в форке отключено; ручной запуск
  остаётся возможен, но выпуск идёт только через `release-clod.yml`.
- Остальные workflow апстрима (release.yml, updater.yml, telegram, winget)
  на теги `clod-v*` не срабатывают; удалить или адаптировать их можно позже.
- Канал beta (pre-release + отдельный эндпоинт) — по плану F6.4, когда
  понадобится.
